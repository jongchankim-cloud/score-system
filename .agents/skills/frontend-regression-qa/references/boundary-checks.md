## 1. 실패를 삼키는 호출

`api()`는 응답 상태를 보지 않고 본문만 파싱한다. 그래서 서버가 거부해도 화면에는 성공 토스트가 뜬다.
실제로 학생 삭제가 외래키 제약에 막혔는데 성공한 것처럼 보인 사고가 있었고, 그래서 `apiDelete`가 생겼다(L862 주석).

**판정:** 이번 변경에 DELETE가 있으면 전부 `apiDelete`인지 확인. 성공/실패를 건별로 집계해야 하는 저장이면 `apiRaw`를 쓰고 `.ok`를 검사하는지 확인.
`await api(...)` 뒤에 곧바로 `showToast('✅ ...')`가 오는 새 코드는 의심 대상이다.

## 2. admin ↔ index 규약 이중화

`ITEM_KEYS` · `DEFAULT_ITEM_CONFIG` · `MOCK_ITEM_KEYS` · `DEFAULT_MOCK_ITEM_CONFIG` · `normalizeItemConfig`가 두 파일에 각각 있다.

**판정:** 두 파일의 해당 블록을 나란히 출력해 문자 단위로 비교한다. `audit-wiring.sh`가 1차로 잡지만,
`normalizeItemConfig`의 **로직**(정규화 규칙, 기본값 대체 조건)은 스크립트가 비교하지 못하므로 직접 읽고 대조하라.
어긋나면 오류가 나지 않고 학부모 화면의 총점·평균·커트라인 판정만 조용히 달라진다 — 가장 발견이 늦는 종류의 버그다.

## 3. 부분 저장(PATCH) 규칙

`saveAllScores`(L1840)는 기존 행이 있으면 `student_id`/`week_id`를 뺀 PATCH를 보낸다.
그리고 **비활성 항목의 점수 컬럼은 payload에 아예 넣지 않는다** — 그래야 항목을 껐다 켰을 때 과거 점수가 살아 있다.

**판정:** 저장 payload 구성 코드를 바꿨다면, 비활성 항목 컬럼이 payload에 `null`로라도 들어가지 않는지 확인.
`null`을 넣는 순간 과거 데이터가 지워진다. 되돌릴 수 없는 종류의 회귀다.

## 4. 복제된 문자 발송 파이프라인

5개 발송 경로(`tab-sms`, `tab-absent-sms`, `tab-clinic-sms`, `tab-score-sms`, `tab-uncert`②)가 같은 골격의 복제본이다.

**판정:** 한 경로에서 버그를 고쳤다면 나머지 4개에서 같은 패턴을 grep해 동일 결함이 있는지 확인하고,
있으면 "같은 결함이 N곳에 더 있음"을 보고한다(요청 없이 고치지는 않는다).
수신처 필드(`phone` = 학부모 / `student_phone` = 학생)가 뒤바뀌지 않았는지도 매번 확인 — 잘못 나가면 되돌릴 수 없다.

## 5. 상호 배타 상태의 불변식

- 모의고사: `absent=true`면 모든 항목 점수와 `retest_pass`가 NULL이어야 한다. 점수와 미응시가 동시에 남으면 안 된다.
- 주차 점수: `no_homework=true`면 `homework_rate`는 NULL이어야 한다.
- 재시험 체크박스: 커트라인 미달(`isBelowCut`)일 때만 보인다. `retest_pass`는 통과한 항목만 담고, 비면 NULL이다.
- 모의고사 저장: 항목 점수를 저장하면 그 합계를 레거시 `score` 컬럼에도 반드시 채운다(학부모 화면이 이 컬럼을 쓴다).

**판정:** 관련 코드를 건드렸다면 각 불변식이 저장 경로와 렌더 경로 **양쪽**에서 유지되는지 확인.

## 6. 하위 호환

- `item_config`가 NULL인 과거 주차/모의고사는 기본값으로 계속 동작해야 한다.
- `mock_scores.score`만 있고 항목 컬럼이 없는 과거 데이터도 학부모 화면에서 총점이 보여야 한다.

**판정:** 정규화 함수나 렌더 함수를 바꿨다면 "이 값이 NULL/없음일 때" 경로를 코드에서 짚어 확인하라.
운영 DB에 과거 데이터가 남아 있으므로 이 경로는 지금도 실행된다.

## 7. 저장 안 된 변경 경고

`scoreDirty` / `mockDirty` 전역이 미저장 상태를 추적하고, `switchTab`(L915)이 탭 이동 시 경고한다.
점수/모의고사 입력 UI에 새 입력 요소를 추가했다면 그 요소의 변경도 dirty 플래그를 세우는지 확인하라.
안 그러면 조교가 입력한 값이 경고 없이 사라진다.
